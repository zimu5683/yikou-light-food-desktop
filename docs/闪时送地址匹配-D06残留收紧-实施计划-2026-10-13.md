## 1. 问题：D06 本体修好之后留下的"翻转"

D06 本体修复给地址包含匹配加了"门牌数字边界"：被包含片段两侧相邻字符只要有一侧是数字就判不同址。效果是"…B10"不再顶包"…B1"（漏单修复），**代价**是"同一栋楼 + 房间号/单元/楼层"的写法也被判成不同地址：

- 站内概要地址是"…B1 101室 / …B1 2单元 / …B1101"这类写法时，对账 `confirmed` 为空 → 工具认为"这单还没下" → 又提交一遍 → **重复下单**（方向与 D06 本体相反）。
- 触发链（唯一调用链，改动只影响这一处）：
  `_addresses_compatible`（`app/sss.py:1458-1485`）判不同址 → `_fingerprint_compatibility`（`app/sss.py:1488-1511`）判 conflict → `_reconcile_tasks`（`app/sss.py:1821`）把站内记录当"他人订单"忽略 → 任务留在 `missing` → 下单前对账 `if not initial.missing` 不成立 → 重新 POST。

### 1.1 实测判定矩阵（修复前 vs 现行）

判定输入为折叠后的地址串（`_address_combo` = `addressDetail + doorNum`，经 NFKC + casefold + 去空白；站内概要整串同样折叠）。任务侧一律为"…东湖校区b1"。

| 站内概要地址写法（任务 = …B1） | 修复前（纯包含） | 现行（数字边界） | 性质 |
| --- | --- | --- | --- |
| …B10（另一栋楼） | 判同址 → 漏单 | 判不同址 | ✔ D06 本体修复目标 |
| …B12 | 判同址 → 漏单 | 判不同址 | ✔ |
| …B1 101室（同栋、写了房间号） | 判同址 | 判不同址 | ✘ 翻转：可能重复下单 |

## 2. 已确认口径（2026-10-13）

1. 站内写法带 **房号 / 单元 / 楼层**（"…B1 101室 / …B1 2单元 / …B1 3层"）→ **算同一送餐点（判同址）**。
2. 站内写法是"楼号后直接跟数字、后面**没有**"室/单元/层"等字样"的裸数字串（"…B1101"）→ **判同址**（把裸数字串按房号理解；宁可按"已有单"处理，也不重复下单）。
3. **1–2 位**数字扩展（"…B10 / …B12 / …B100"、"12 vs 1202"、"1 vs 11"）→ 仍**判不同址**（保住 D06 本体保护与既有回归用例）。
4. 其余容差（缺省份前缀、大小写、号/栋/X 尾缀）保持现状不变。

## 3. 修法设计（`app/sss.py`：1 个函数 + 2 个常量）

### 3.1 新增常量

放在 `_address_combo` / `_addresses_compatible` 同段（`app/sss.py:1448` 一带）：

```python
# 楼栋内部的房号/单元/楼层后缀：数字串后面出现这些字样时，数字按"楼内编号"理解。
# 刻意不含 栋/楼/号/座/区——它们可能是楼栋名的一部分（如"…B12栋"），纳入会把
# 另一栋重新误判成同一栋（D06 式漏单）。集合刻意留窄，可按真实样例再扩。
_ROOM_SUFFIX_MARKERS = ("室", "房", "间", "单元", "层")
# 无字样、纯数字串的最小位数：≥3 位按房号理解；1–2 位与楼栋号（B10/B12/B100）无法区分。
_ROOM_DIGIT_RUN_MIN = 3
```

### 3.2 `_addresses_compatible` 改为四档

保留既有"折叠后相等"与"非数字边界包含"两档；在"右邻是数字且左邻不是数字"处新增两档：

```python
start = longer.find(shorter)
while start != -1:
    end = start + len(shorter)
    left = longer[start - 1] if start > 0 else ""
    right = longer[end:end + 1]
    if not (left.isdigit() or right.isdigit()):
        return True                     # 既有档：非数字边界包含（容差）
    if right.isdigit() and not left.isdigit():
        run_end = end
        while run_end < len(longer) and longer[run_end].isdigit():
            run_end += 1
        if longer[run_end:].startswith(_ROOM_SUFFIX_MARKERS):
            return True                 # 新增档 1：数字串后紧跟 室/房/间/单元/层
        if run_end - end >= _ROOM_DIGIT_RUN_MIN:
            return True                 # 新增档 2：裸数字串 ≥3 位（按房号理解）
    start = longer.find(shorter, start + 1)   # 其余情况继续找下一个出现位置
return False
```

- 函数保持纯函数、**签名不变**，无调用点改动（`_fingerprint_compatibility` 是唯一调用方）。
- 同并重写函数 docstring：说明三级/四档口径与"为什么不含 栋/楼/号"。
- 左邻是数字的情况（片段嵌在更长的数字里）保持保守，不套用新增两档。

### 3.5 备选方案与否决理由

- **按"楼栋号 ≤2 位"从 `app/delivery_point.py` 的 `_RE_BLDG` 反推阈值**：与既有用例"12 vs 1202 判不同址"、"B100 保护"直接冲突，否决。
- **把 栋/楼/号/座 也纳入"楼内后缀"集合**：会把"…B12栋"判成与 B1 同址，重新引入 D06 式漏单，否决。
- **"无法判定 → 整批停（fail-closed）"**：任何疑似写法都会挡住整批对账，影响面过大，本次不采用。

## 6. 残留与已知边界（实施后写回修复记录）

1. **1–2 位数字扩展（B10/B12/B100）仍判不同址**：与楼栋号无法区分，这些形式的重复下单风险保留（与 D06 本体保护同向，属既定口径）。
2. **"…B12单元"按"B1 的 2 单元"理解**（已确认单元算同处）；若真实数据表明是 B12 的单元，回调 `_ROOM_SUFFIX_MARKERS`。
3. **≥3 位裸数字按房号理解**：若现实中存在 3 位以上楼栋号，属"漏单"方向误判（已选此口径）。
4. 真实平台概要地址的实际写法仍未线上确认——本次结论全部来自离线探针，`app/sss.py` 的折叠逻辑（去空白）意味着"B1 101室"会折成"b1101室"，线上是否出现该写法需样例验证。

**与交接说明的两处刻意差异**（都属于「不扩大本次改动范围」）：

1. **放宽触发不绑定分类名**。交接说明的条件是「结果分类 = uncertain」；桌面版把
   `success=false` 的平台响应归为「显式失败（可人工重试）」而不是 uncertain（两项目
   语义不同，交接说明也要求**不要**把桌面版改成服务端的「未发送/不确定」语义）。
   因此桌面版按「响应特征（内部异常 + `IndexOutOfBounds`）+ 耗时 ≤1.5 秒 + 状态为
   拒绝/未知」触发放宽，两种分类都覆盖；分类、未决日志与重发路径一行未动。
2. **服务端 §4.3 的已知缺口随实现一并保留**：`penalize()` 只更新 `_interval`，不重算
   `_next_allowed`，加罚后的下一单可能仍按旧许可时间发出（下一单及之后记录的是新间隔）。
   桌面版当前与服务端行为一致；`docs/闪时送周期失败与序号跳号排查-2026-10-09.md` §8.3
   建议的修正（让生效间隔与诊断一致）另行决定。

未做：真机验证（离线用例与全量测试已过）；没有替用户改变并发或间隔配置
（默认 2.5 秒对所有配置立即生效，`sss_submit_min_interval_s = 0` 可关闭）。

以下是服务端侧交接说明原文。

## 1. 背景：为什么要做这次修改（根因已定位）

现场（2026-10-09，服务端版，95 单、4 路并发）：单轮只有 33 单成功，后续补跑四轮成功率恒约 **1/3**，且逐单统计显示成功位置严格「**每 3 单 1 单**」。原始日志特征：

- 失败请求约 **0.36 秒**内返回：HTTP 200 + `code=500` + `java.lang.IndexOutOfBoundsException: Index: 0, Size: 0`（平台自己的内部异常）；
- 成功请求约 **7.4 秒**完成；33 个成功 × 约 **2.1 秒** ≈ 本轮总耗时 69.2 秒——成功几乎严格按平台节奏铺满全程；
- 同一订单首轮失败、次轮成功（请求体完全相同）→ 失败与订单内容无关，只与发送节奏有关。

结论：**平台对同一账号的建单受理上限约 1 单 / 2.1 秒**。4 路滚动补位下，被驳回的请求 0.36 秒即回、该车道立刻补发下一单，实际发送节奏被推到约 **1.37 POST/秒 ≈ 3 倍超速**，所以每轮约 2/3 被驳回。更严重的是：**每个请求（成功或失败）都会消耗一个平台订单序列号**——用户实测实际订单不到 100 单而序列号到了 200 多（五轮合计 238 次请求 ≈ 238 个序列号），失败单成了不可见、不扣费的「幽灵订单」。10-08 的另一现场（网页/手动下单也失败、程序“单单重试”（串行）立刻成功）同源。

**注意（不要用这些“修法”）**：把并发降到 1 能规避但极慢且不解决根因；去改“失败分类/重发”逻辑与限速无关，反而会破坏“已发送未知不自动重发”的安全语义。本次只加**发送节奏节流**。

## 2. 修改规格（请逐项一致，便于两个项目对照）

1. **新增配置 `sss_submit_min_interval_s`**（秒）：
   - 出厂默认 **2.5**（= 实测受理间隔 2.1s + 余量）；**0 = 关闭节流**；夹紧 **[0, 60]**；解析失败或 NaN → 2.5。
   - **无需迁移逻辑**：旧配置缺这个键 → 直接用默认值 2.5 生效；显式写入的 0 必须原样保留。
   - 字段无界面入口（与 `sss_max_workers` 同策略：改 config.json 生效）。
2. **提交节流闸门（`_SubmitPacer`，线程安全，每轮提交新建一个实例）**：
   - 语义：**任意两次 POST 的“起点”至少间隔 interval 秒**（不是完成间隔）；并发路数**保持 4 不变**（4 路 + 2.5s 间隔 ≈ 同时最多 3 个在途，低于平台上限）。
   - 在每次真实 POST **之前**调用 `wait()`；**必须放在请求计时开始之前**（耗时统计仍只量 HTTP 本身）。
   - interval ≤ 0 时 `wait()` 直接返回 True —— 0 = 与改动前行为完全一致。
   - 等待期间检测到 停止 / 401 / 余额不足 → 返回 False，调用方把该任务记为**「未发送」**（请求确实没有发出；401 重登后按未发送语义允许补发）。**不得引入任何新的自动重发。**
3. **自适应放宽**（平台若再收紧时自保）：
   - 触发条件（三个同时满足）：结果分类 = uncertain；请求耗时 ≤ **1.5 秒**；响应体是平台内部异常且 message 含 `IndexOutOfBounds`。
   - 动作：interval **× 1.5**，上限 **10 秒**；每次真正放宽打印一行日志（到达上限后静默）。
   - 只影响节奏，**不改变任何结果分类与「不自动重发」语义**。
4. **可观测（字符串建议原样对齐，便于跨项目 grep）**：
   - 开始行追加：`，提交最小间隔 {interval:g}s`（仅 >0 时）；
   - 本轮汇总行追加：`；提交最小间隔 {pacing:g} 秒`；
   - 放宽日志：`平台快速驳回（疑似建单受理超速）；提交最小间隔自动放宽到 {x:g} 秒（结果分类与重发语义不变）`；
   - 诊断记录新增字段 `min_interval_s`（该请求**发出时生效**的间隔，保留 3 位小数）。
5. **保持不动的部分（重要）**：并发仍 4；「已发送未知」仍不自动重发；超时/5xx/内部异常仍按 uncertain 处理；journal / 对账语义不动；dry-run / 预检路径不产生 POST、不受节流影响。

## 3. 参考实现（服务端原文）

常量：

```python
_SUBMIT_FAST_REJECT_MAX_S = 1.5          # 「快速驳回」耗时上限
_SUBMIT_INTERVAL_PENALTY_FACTOR = 1.5    # 每次放宽倍数
_SUBMIT_INTERVAL_PENALTY_MAX_S = 10.0    # 放宽上限
_DEFAULT_SSS_SUBMIT_MIN_INTERVAL_S = 2.5 # 出厂默认间隔
_SSS_SUBMIT_MIN_INTERVAL_CEILING_S = 60.0
```

节流闸门（桌面版同名实现见 `app/sss.py::_SubmitPacer`）：

```python
class _SubmitPacer:
    def __init__(self, interval_s: float) -> None:
        self._lock = Lock()
        self._interval = max(0.0, float(interval_s or 0.0))
        self._ceiling = max(_SUBMIT_INTERVAL_PENALTY_MAX_S, self._interval)
        self._next_allowed = 0.0  # time.perf_counter 时间基准

    def wait(self, stop_event=None, halted=None) -> bool:
        """阻塞到可以发送下一次 POST；返回 False = 等待期间停止/中止（未发送）。"""
        if self._interval <= 0.0:
            return True

        def aborted() -> bool:
            if halted is not None and halted():
                return True
            return stop_event is not None and bool(stop_event.is_set())

        while True:
            if aborted():
                return False
            with self._lock:
                now = time.perf_counter()
                if now >= self._next_allowed:
                    self._next_allowed = now + self._interval
                    return True
                delay = min(self._next_allowed - now, 0.25)
            time.sleep(delay)

    def penalize(self) -> float | None:
        with self._lock:
            if self._interval <= 0.0 or self._interval >= self._ceiling:
                return None
            self._interval = min(self._ceiling,
                                 self._interval * _SUBMIT_INTERVAL_PENALTY_FACTOR)
            return self._interval

    @property
    def interval(self) -> float:
        with self._lock:
            return self._interval
```

提交循环接线（桌面版对应 `_submit_tasks_concurrent` 的 `run_one`）：

```python
def run_one(task):
    if stop_event.is_set():
        return task["identifier"], "stopped", ""
    if not pacer.wait(stop_event, halted):        # halted() = stop/401/余额任一

        return task["identifier"], "stopped", ""
    interval_at_send = pacer.interval
    started = time.perf_counter()                 # 计时从这之后开始
    ...
    response = submit(task["payload"]);  _check_success(response)
    ...
    elapsed = time.perf_counter() - started
    if (state == "uncertain" and elapsed <= _SUBMIT_FAST_REJECT_MAX_S
            and _is_rate_reject_response(response)):
        widened = pacer.penalize()
        if widened is not None:
            _emit(callback, "平台快速驳回（疑似建单受理超速）；"
                            f"提交最小间隔自动放宽到 {widened:g} 秒"
                            "（结果分类与重发语义不变）")
    record = submission_diagnostic(...)           # 现有诊断
    record["min_interval_s"] = round(interval_at_send, 3)
```

超速特征识别：

```python
def _is_rate_reject_response(response) -> bool:
    """平台「受理超速」特征：内部异常且 message 含 IndexOutOfBounds（空列表取 0）。"""
    if not isinstance(response, dict) or not is_internal_error_payload(response):
        return False
    message = str(response.get("message") or response.get("msg") or "")
    return "IndexOutOfBounds" in message
```

（`is_internal_error_payload` 用你们现成的等价判断即可：message/msg 含 Java 异常类名，或有 `exception`/`stackTrace` 等字段。桌面版原先没有这个判定，本次在 `app/api_client.py` 新增。）

配置解析与兜底解析（runner 侧）：

```python

except (TypeError, ValueError):

# runner 侧（配置残缺/坏值时按出厂默认保守节流，而不是全速）：
def resolve_submit_min_interval_s(config) -> float:
    try:
        interval = float(getattr(config, "sss_submit_min_interval_s",
                                 _DEFAULT_SSS_SUBMIT_MIN_INTERVAL_S))
    except (TypeError, ValueError):
        interval = _DEFAULT_SSS_SUBMIT_MIN_INTERVAL_S
    if interval != interval:  # NaN
        interval = _DEFAULT_SSS_SUBMIT_MIN_INTERVAL_S
    return max(0.0, min(_SSS_SUBMIT_MIN_INTERVAL_CEILING_S, interval))
```

## 4. 验收标准

**离线用例（服务端已实现；桌面版同名移植于 `tests/test_sss.py` / `tests/test_config_boundaries.py`）**：

| 用例 | 断言点 |

**真机观察**：开始行出现 `提交最小间隔 2.5s`；一轮 95 单总耗时 ≈ 95×2.5s ≈ 4 分钟（+尾延迟 7-9 秒）；**不再成批出现** `IndexOutOfBoundsException` 快速驳回（若出现，日志会有「自动放宽」一行，属预期的自保行为）。

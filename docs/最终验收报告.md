## 3. R01–R12 关闭清单

| 编号 | 状态 | 复现 / 反证 | 改动与回归证据 | 遗留风险 |
|---|---|---|---|---|
| **R01** 文件锁所有权/重入/异常清理 | **已修复** | 修复前实测两个缺陷：① 交错释放（先释放先获取者）后锁**永远不释放**（`LockTimeout`）；② `_try_lock` 抛 `RuntimeError`（无锁原语）后线程锁泄漏 | 资源（fd + 线程锁）从实例移到共享 `_LockRecord`，只有把计数减到 0 的那次才真正解锁；任何异常路径都归还资源；锁身份用 `realpath`+`normcase` 归一（别名共用一把锁）；批次锁与数据锁**拆成两个文件**并写明锁顺序 | Windows `msvcrt` 分支仍是静态实现（无法在本机执行） |
| **R02** 取锁后重读权威状态 | **已修复** | 真双进程验证：子进程在"已读空日志、尚未取锁"时父进程写入未决记录 → 修复前 `posts=1`（真的下单了），修复后 `posts=0`、`status=blocked_by_uncertain` | `_begin_submission()` 在取得批次锁后重新 `blocking_state()`；读取失败也拒绝（fail-closed） | 无（真实平台未跑） |

## 6. 投产前必须做的事（给业务负责人的清单）

1. **配置核对**：确认生效目标是**测试副本**（不是正式表）、日期、账号、平台 origin、并发与名单来源都符合预期；`sss_dry_run` 先保持开启。
2. **备份**：备份 `config.json`、`wps_sync_state.json`(+`.journal`)、`sss_uncertain.json`(+`.review.json`)；确认能读回备份。**不要**只回滚本地账本就重传。
3. **WPS 受控集成**（授权测试副本后）：预览 → 核对逐表统计与阻断提示 → 上传 → 故意重复上传一次（应为全 noop、零写入）→ 人为制造一次回读失败 → 在「云同步恢复」里走一遍四个决策（`cloud_verified` / `cloud_untouched` / `retire_guarded` / `keep`），确认恢复入口前后云端只有读取。
4. **闪时送受控集成**（授权测试账号/名单后）：`dry_run` → `preflight` → 小批真实提交（≤ 2 单）→ 确认站内只读核对能匹配 → 故意让一次请求超时/断网 → 确认留下 `unresolved` 且再启动被阻断 → 用「只读核对 + 确认站内没有」解除。
5. **目标平台冒烟**：在实际使用的系统上启动最终候选程序，检查配置目录、文件锁、系统密钥环（含 Linux 无 SecretService 时的降级提示）、内置 Chromium、Playwright fallback、退出与重启。
6. **首次正式批次**：先预览/预检，人工核对摘要后再执行；出现未知/重复/账本异常立即停止新写入，只读核对后再处置。

## 7. 遗留风险与已知限制

| 风险 | 说明 | 已做的缓解 |
|---|---|---|
| WPS 接口无远端 CAS | 只读复核与首次写入之间仍有窗口 | 令牌+上下文+计划指纹+账本版本三条闸门 + 意图日志；窗口内异常进入恢复态 |
